# Contributing

## Getting started

1. Fork the repository and clone your fork.
2. Copy the OutSystems platform assemblies into `Source/NET/Bin/` (see [Build and Deployment](README.md#build-and-deployment)). They aren't committed because they are proprietary.
3. Open `EnvironmentInfo_Ext.xif` in Integration Studio. To build only the .NET code, use MSBuild:
   ```
   msbuild Source/NET/EnvironmentInfo_Ext.csproj /p:Configuration=Release
   ```

## Workflow

1. Create a branch from `main`:
   ```
   git checkout -b feature/short-description
   ```
2. Make the change in focused commits. Commit the updated `EnvironmentInfo_Ext.xif` and copy its source files into `Source/NET/` in the same commit, so the two never disagree.
3. Check that the extension compiles with no warnings (Integration Studio Verify, or the MSBuild command above).
4. There are no automated tests. Check every changed action from a test module, in a screen and in a Timer.
5. Add your change to CHANGELOG.md.
6. Open a pull request against `main` that explains the change and why.

CI fetches the OutSystems platform assemblies with the private `OS_DEPS_SSH_KEY` secret. GitHub doesn't give secrets to pull requests from forks, so for those CI skips the build and says so in a warning. Build locally before opening a PR from a fork.

## Code conventions

- Target .NET Framework 4.8, and use C# 6 language features at most, like the existing code.
- Match the existing style: tabs, XML doc comments on every action, and the `ss`/`Mss` naming of the generated code.
- `Interface.cs`, `Structures.cs`, `Records.cs`, `RecordLists.cs` and `Entities.cs` are generated by Integration Studio. Change actions and structures in Integration Studio first, then update the code.
- Keep hand-written code in `EnvironmentInfo_Ext.cs`.

## Reporting issues

Include:
- the extension version or commit;
- the OutSystems 11 platform version;
- the action and inputs used;
- the full error message or the unexpected behaviour.
